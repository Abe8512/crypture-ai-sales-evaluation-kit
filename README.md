# AI sales workflow evaluation kit

Free, editable worksheets from [Crypture](https://crypture.ai) for testing AI sales conversations, lead follow-up, administrative bookings, and human handoffs. Use the same scenarios across vendors so a polished demonstration does not substitute for a working process.

These are educational procurement templates, not software, a benchmark of vendor performance, a legal opinion, or a healthcare certification. The sample inquiry is fictional. The repository contains no Crypture application source, credentials, customer data, or patient information.

## Download the worksheets

- [Vendor test scorecard](ai-sales-test-scorecard.csv): twelve scenarios covering approved answers, price objections, unsupported promises, clinical boundaries, purchase evidence, staff takeover, opt-outs, unanswered inquiries, failed connections, unavailable options, duplicate events, and channel handoffs.
- [Inquiry response log](inquiry-response-log.csv): separate timestamps for arrival, queue receipt, acknowledgment, first useful answer, two-way contact, and staff takeover, plus next action and verified outcome.

Open either CSV in Excel, Google Sheets, or another spreadsheet editor. Keep the original as a clean template. Delete the example row before recording observations, and use fictional test identities. Do not upload private evaluation results, contact details, credentials, payment information, or health information to a public repository.

## Run a useful evaluation

1. Choose one workflow and one measurable outcome. Examples are a verified purchase, an accepted appointment, or a request assigned to the correct staff member. A link shared, a positive reply, a request captured, and a completed action are different events.
2. Write the permitted answer sources, supported system actions, eligibility rules, contact limits, and staff owner before testing. A vendor name or integration logo does not establish what can be read or written.
3. Give each provider the same fictional requests, approved information, and failure cases. Record what the system actually does in the scorecard, rather than scoring a verbal promise.
4. Assign an owner and review date to every failure. Treat critical scenarios individually: a high average does not compensate for ignoring an opt-out, inventing a clinical answer, or confirming a purchase that never completed.
5. Re-test fixes with the same scenario and a meaningful variation. Keep the observed result and evidence in your private evaluation system, outside this public template repository.

## Measure response time without counting an acknowledgment as an answer

Use the response log to distinguish the point when a request arrived from the point when the buyer received useful help. In the fictional row, the inquiry arrives at 10:00:00, the system acknowledges it at 10:00:35, and the first useful answer appears at 10:04:00. The acknowledgment time is 35 seconds; the first useful response time is four minutes. Neither number is a measured Crypture result.

For a real pilot, agree the time zone, business-hours treatment, source event, substantive-answer definition, and handling of unanswered inquiries. Report the share of inquiries that never receive a useful response alongside response-time distributions. A fast average among successful conversations can hide unresolved requests.

## Verify the outcome and cost

Count completed purchases only when the accepted completion event is available. Separate appointments requested, appointments accepted, and visits attended. Pause or stop selling after the agreed completion signal, a staff takeover, or an opt-out, as appropriate for the workflow.

Compare a pilot with a defined baseline or a suitable comparison group. Include implementation, provider usage, human review, support, discounts, refunds, and ongoing operating effort. A conversation touching an order is not proof it caused an additional order. Do not present total attributed revenue as incremental profit.

For healthcare-related work, separate approved administrative or product information from clinical decisions. Route suitability, medication, treatment, and urgent clinical questions to qualified staff under the business's approved procedure. Do not use these worksheets to infer that a deployment is HIPAA compliant; review agreements, data flows, eligible services, access, retention, and channel behavior separately.
